# Продукт и переходы

## 1. Сохраняемый интерфейс

Главная: контекст студента → один конкретный Hero → существующий вертикальный роадмап из «До приезда», «После приезда», «Во время учебы». Сохранить текущие шрифты, цвета, отступы, иконки, карточки, RU/EN, нижние вкладки «План / Событие / Мои данные» и MAX Back.

Нажатие на раздел открывает отдельный экран. В нем видны текущие, выполненные и будущие задачи с текстовыми статусами. Нажатие на задачу открывает ее карточку. Back возвращает в исходный раздел с сохранением позиции; вход из Hero возвращает в План. Никаких длинных списков и раскрывающихся разделов на главной.

## 2. Онбординг: достаточно сведений для первого действия

Не сохранять обещание «четыре вопроса», если вопросов больше. Группировать их по смыслу и раскрывать по ответам. Вопрос о филиале убрать: два текущих вуза — рамка пилота. campus=main может оставаться конфигурацией каталога, но не сообщенным пользователем фактом.

| Блок | Вопросы | Влияние |
|---|---|---|
| Ситуация | Готовлюсь к приезду / уже в России; вуз | Выбор ветки и локальной инструкции |
| Поддержка | Совершеннолетие; учебный статус; основание пребывания | Стандартный маршрут или индивидуальная проверка |
| До приезда | Режим въезда; готовность приглашения/визы; при необходимости форма обучения | Конкретный первый шаг подготовки |
| Уже в России | Дата последнего въезда либо «не знаю»; цель в документах; текущий тип жилья | Эпизод и применимость действий после въезда |
| Уже сделано | Полный/частичный комплект передан? Регистрация получена / подана / не начинали / неизвестно? | Не повторять подтвержденные результаты |
| Известные даты | Виза и регистрация: дата окончания либо «не знаю» | Проверка срочности и точечные уточнения |

Учебный статус «зачислен, занятия еще не начались» обязателен для основной ветки. Не маскировать его как active. Неизвестное не заменять положительным ответом. Неподдержанные статусы ведут к конкретной проверке; заполнение анкеты само не делает их поддержанными.

Жилье до приезда спрашивать, когда оно меняет подготовку/заселение; не блокировать запрос приглашения вопросами о поздних процедурах. Если выбранный вуз использует дату прибытия в город отдельно от даты въезда, спросить ее адресно; не приравнивать эти даты.

Перед записью фактов сохранить существующее согласие и подтверждение сводки. «Уже в России» без даты — контекст, а не выдуманный entry event. При неизвестной дате первым полезным шагом может быть «Укажите дату въезда» с объяснением, где ее найти; будущую подготовку к первому въезду не предлагать.

## 3. Процессы и результаты

ID ниже — семантические обозначения для задания, не готовые значения API/family.

| ID | Раздел | Предусловие | Последовательность результатов | После результата |
|---|---|---|---|---|
| P1 | До приезда | Визовая ветка, применимость подтверждена | Не начинал → запрос отправлен → приглашение получено | Доступна подача на визу |
| P2 | До приезда | Приглашение или иной подтвержденный порядок | Подготовка → документы поданы → виза получена | Подготовка поездки |
| P3 | До приезда | Виза готова либо безвизовый порядок определен | Комплект поездки, порядок прибытия, заселение проверены | Готов к поездке, но въезд еще не произошел |
| A1 | После приезда | Фактический въезд | Дата/цель явно подтверждены | Обновить применимые задачи нового эпизода |
| A2 | После приезда | Применимый эпизод | Самостоятельная проверка документов → без расхождений / есть вопрос | Результат проверки либо консультация |
| A3 | После приезда | Применимый эпизод | Не передавал / частично → весь комплект передан | Не завершает регистрацию автоматически |
| A4 | После приезда | Текущее место проживания, применимость | Подготовка → подано → ожидается → документ получен | Сохранить результат, запросить недостающую дату отдельно |
| A5 | После приезда | Требует проверки | Вопрос специалисту → отправлен → индивидуальное разъяснение | Применимые процедуры определяет подтвержденное правило/проверка |
| S1 | Во время учебы | Визовая ветка и текущий цикл | Подготовка продления → подача → результат | Новый документ и новый цикл |
| S2 | Во время учебы | Текущее проживание/цикл учета | Подготовка → подача → результат | Новый документ и новый цикл |

Безвизовый сценарий пропускает P1/P2. Согласование прибытия показывать по локальной применимости, не всем автоматически. P3 допускает отдельные подпункты/задачи, если у них независимые исполнитель, срок или результат; копии одного комплекта остаются чек-листом.

## 4. Три разных измерения

1. Положение на маршруте: до въезда / после въезда / сопровождение во время учебы.
2. Применимость и доступность: применимо, нужно сведение, нужна проверка, зависит от будущего события, не требуется.
3. Результат: не начато, в работе, подано/ожидание, получен результат.

Не смешивать их в один completed. Нажатие «Открыть» не завершает задачу. Подача не равна получению. Отправка вопроса не подтверждает юридическую применимость. Галочка — конкретный self-report, а не проверка вузом.

Все разделы можно просматривать всегда. Действие с настоящей зависимостью не разрешать подтвердить без основания; предыдущее выполнение вне сервиса можно сообщить явным фактом. Независимые действия остаются доступны параллельно.

Факт въезда переводит контекст в «После приезда» без требования галочек P1–P3; неизвестные прошлые задачи не становятся выполненными. Для текущего раздела «Во время учебы» достаточно известных результатов основных первичных действий A1–A4 в данном сценарии, но это не завершает A5 и другие применимые задачи. Сохранять незакрытые проверки видимыми, даже если их раздел уже не текущий. Этап нельзя считать целиком завершенным при неизвестной применимости части задач.

## 5. Hero и сортировка

Сохранять серверный выбор приоритета: срочные/просроченные доступные задачи → существующий priority bucket → ближайшая подтвержденная дата действия → стабильный порядок. Не путать дату окончания документа со сроком подачи. Hero может вести в любой раздел.

Ожидание результата показывать в Hero, если более важного доступного действия нет. Тогда объяснить, у кого/как узнать результат, и дать «Результат получен», а не повторную подачу. Уточнение показывать, когда оно разблокирует следующий шаг; не ставить все недостающие поля впереди срочных задач. Если применимых действий нет — честное состояние и конкретная адресная помощь, не общая задача «Проверьте следующие действия».

Внутри раздела сохранить зависимости процесса; параллельные доступные действия сортировать по срочности. Будущие видимы с причиной «после получения…». Неприменимые исключаются из рабочего прогресса. Уточнения не входят в знаменатель как заведомо обязательные процедуры. Не делать task duplicate для Hero и списка.

## 6. Редактирование и события

Из задачи — точечная форма нужных полей. Из «Мои данные» — соответствующий раздел профиля. Новое событие, исправление прежнего и редактирование обычного профиля — разные операции. Не отправлять человека в онбординг заново.

Подтверждение → атомарная запись → серверный пересчет → короткое объяснение изменений → обновленный План. Ошибка/отмена сохраняет черновик, не меняет факты. Reload и повтор запроса не создают дубли. История содержит исправления/отмены и причину завершения. Повторный въезд и переезд не стирают прежнюю историю.
