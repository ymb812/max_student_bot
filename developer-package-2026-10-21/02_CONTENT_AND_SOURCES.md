# Карточки, источники и сроки

## Обязательная структура

Короткий глагольный заголовок; кто выполняет; конкретные действия; где выполнить/проверить; что подготовить; ожидаемый результат; точный CTA подтверждения; альтернативный путь при ошибке; источник и навигационная подсказка; отдельный блок сроков. Использовать существующие блоки приложения. Не добавлять все блоки, если они пусты или не нужны.

| Процесс | Что написать в карточке | Результат и CTA | При затруднении |
|---|---|---|---|
| P1 приглашение | Уточните у ответственного отдела своего вуза комплект и канал запроса; после отправки проверьте способ получения результата | «Запрос отправлен», затем «Приглашение получено» | Контакт подразделения, а не общая главная вуза |
| P2 виза | Подготовьте подачу по инструкции соответствующего консульства; после подачи проверяйте результат указанным при подаче способом | «Документы на визу поданы» / «Виза получена» | Не направлять за выдачей визы в университет; вуз помогает с приглашением |
| P3 поездка | Три пункта: документы для поездки; порядок прибытия в вуз; порядок заселения. Для каждого — свой источник/ответственный | «Все готово к поездке» после явных отметок трех пунктов | Не блокировать въезд отсутствием отметок подготовки |
| A1 въезд | Укажите фактическую дату въезда и цель, отраженную в документах | «Подтвердить въезд» | «Не знаю дату» → точечная помощь; не ставить сегодняшнюю дату |
| A2 проверка | «Сначала самостоятельно сверьте данные в полученных документах по списку ниже». Список включает идентификационные данные и даты, цель въезда там, где она предусмотрена; состав сверить с применимым источником | «Проверил(а), расхождений не нашёл(ла)» | «Есть ошибка или вопрос» → международный отдел, перечень сведений для обращения; не completed |
| A3 комплект | «Вы уже передали документы в [название отдела] после последнего приезда?» Показать точный вузовский комплект | «Передал(а) часть» / «Весь комплект передан» | Уточнить недостающие позиции; звонок не равен передаче |
| A4 регистрация | Уточните у принимающей стороны по текущему жилью, как подать документы и получить результат | «Документы поданы» / «Регистрация получена»; дату окончания запросить отдельно, если неизвестна | Контакт зависит от жилья. Получение документа не означает, что его проверил сервис |
| A5 процедуры | Конкретный вопрос: какие процедуры применимы и как проверить действительность ранее полученных результатов | «Вопрос отправлен» → ожидание; дальнейший результат не превращать автоматически в юридическое решение | Не писать, что всем обязательны одни и те же процедуры |
| S1/S2 продления | Указать документ и текущий цикл; комплект/канал/дата подачи по применимому правилу | Подача и получение нового документа — отдельные подтверждения | Известный близкий срок должен влиять на Hero |

Копирайт — проектный текст, не новая правовая норма. В обеих языковых версиях сохранять смысл. Не добавлять советы о пересечении границы или исправлении правового статуса без проверенного источника.

## Источник не должен заменять инструкцию

Прямая ссылка на раздел предпочтительна, но не обязательна. При отсутствии якоря: «Где искать: [точный заголовок страницы] → [точный заголовок раздела]»; «Что найти: [конкретный комплект/порядок]»; кнопка «Открыть инструкцию». Не выдумывать anchor и названия меню. Если контакт нужен для исполнения, размещать контакт рядом с действием. Одна общая ссылка не покрывает разные роли университета, консульства и принимающей стороны.

Предлагаемые метаданные: source URL/title, section label, что найти, дата проверки, подтвержден ли путь, контакт/роль. Конкретные API-ключи выбирает разработчик. Для неподтвержденного раздела дать известную страницу и честное действие связи с отделом; проверить путь до приемки карточки.

## Проверенные и непроверенные пути

Проверка 21.10.2026: [страница СПбГУПТД](https://prouniver.ru/foreign/visa/) доступна. Для P1/P2 использовать раздел «До въезда. Оформление приглашения»; для A1/A2 — «Порядок въезда в РФ»; для A3/A4 — «Миграционный учет». Для контактов и продлений на странице есть отдельные блоки; точный заголовок и актуальные данные сверить при заведении карточки. Путь внутри страницы допустим вместо глубокого URL. Здесь подтверждена навигация, а не применимость каждой нормы каждому студенту.

[Страница ЛЭТИ](https://new.etu.ru/ru/home/international/po-priezde) есть в текущем каталоге, но инструмент чтения не смог получить ее содержимое при этой проверке. Не считать ее недоступной всем пользователям. Разработчику проверить в браузере разделы, комплект и контакты. Не копировать инструкции СПбГУПТД в ЛЭТИ. [Медицинская страница ЛЭТИ](https://new.etu.ru/ru/home/studentam/medicina-dlya-studentov/medicina-dlya-inostrancev/) — ссылка из каталога, в этой задаче содержимое не проверено.

Консульский источник для визы зависит от страны/места подачи. Не показывать выдуманный универсальный URL выдачи виз. При отсутствии конкретизации объяснить, что нужна инструкция учреждения, куда пользователь подает документы, и предложить адресную помощь.

## Решение пользователя о демонстрационных днях

В демонстрационных правилах, где в исходном тексте указаны дни без типа, использовать рабочие дни. Явно указанные календарные дни и часы сохранять. Убрать «единицу времени уточнить»; не добавлять «срок принят для пилота» в каждой карточке. Общее обозначение тестовой версии достаточно.

Это нормализация демонстрационных данных, не исправление текста первоисточника и не подтверждение правового толкования. Внутренне сохранить исходную формулировку, unit_original, unit_effective=working либо аналогичные метаданные, основание demo_assumption и версию правила. Не менять реальную нормативную запись молча. Перед использованием реальными студентами единицы подтверждаются владельцем содержания.

Пример: местное действие СПбГУПТД из seed с 2 днями и unit=unspecified → в демонстрационном правиле «в течение 2 рабочих дней». Часы ЛЭТИ и явно календарные интервалы остаются прежними. Никакой глобальной замены слова «дней» в базе.

Для вычисления даты рабочие дни требуют версии календаря, учета переносов/праздников и определенной конвенции включения даты события. Рекомендуемая явная конвенция демо: отсчет со следующего дня; 2 рабочих дня от пятницы без праздников → вторник. При непроверенном календаре показывать текстовый интервал без фиктивной точной даты. Часовые ограничения и график приема — отдельные условия.
