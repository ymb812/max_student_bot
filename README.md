# Рядом — MAX Foreign Students

Персональный план иностранного студента СПбГУПТД и ЛЭТИ в MAX. Профиль и подтверждённые события собирают несколько независимых действий; новый адрес, документ или версия университетского правила меняют только соответствующие задачи. История и пользовательские статусы сохраняются.

Это MVP по `docs/max_foreign_students_developer_handoff_MASTER_FINAL_2026_09_27.md`. Федеральные сроки без подтверждённой персональной применимости не рассчитываются. Модельная роль редактора и модельные изменения явно обозначены. Интеграций с МВД, ЕСИА и внутренними системами вузов нет.

Student UI обновлён по `docs/RYADOM_FINAL_UI_UX_LOGIC_SPEC.md`: старт и четыре шага onboarding, План с Hero и тремя доступными этапами, полная карточка задачи, события и фактический diff, профиль с редакторами полей, уточнения и история. M07/M08 относятся к «Во время учёбы», но срочная задача любого этапа может стать Hero. Счётчики и сроки берутся из текущего roadmap. Реализация описана в `docs/RYADOM_UI_IMPLEMENTATION_2026_09_28.md`, приёмка опубликованной версии в обычном браузере — в `docs/BROWSER_ACCEPTANCE_2026_09_30.md`.

Для изолированного локального просмотра: `python scripts/preview_redesign.py`, затем `http://127.0.0.1:8010`. Используется отдельная синтетическая база `.local/ryadom-ui-acceptance.sqlite3`, транспорт MAX выключен. Текущий UI проверен на публичном сайте в обычном браузере; его отдельная проверка внутри настоящего MAX на устройстве не зафиксирована. Прежняя MAX-приёмка относится к предыдущему интерфейсу.

## Запуск

1. Скопировать `.env.example` в `.env`. Для браузерной проверки поставить `DEMO_MODE=true`. Сгенерировать разные случайные ключи `EDITOR_SUTD_KEY`, `EDITOR_LETI_KEY`, `MAINTAINER_KEY`; токен выданного бота указать в `MAX_BOT_TOKEN`.
2. Запустить все локальные компоненты:

```sh
docker compose up -d --build
```

Открыть `http://localhost:8000`. Админка: `/admin`; Swagger: `/docs`; API schema: `/openapi.json`; health: `/health`. По умолчанию порт 8000 слушает только 127.0.0.1. `APP_PORT` и `BIND_ADDRESS` задают host binding. Для публичного доступа нужен TLS reverse proxy или туннель.

Python 3.11; один FastAPI-процесс, SQLite/WAL в volume `max-students_max_data`, frontend без Node build. Redis/PostgreSQL и тяжёлые модели не требуются. Docker выполняет только установку фиксированных зависимостей и копирование кода.

```sh
docker compose stop
docker compose up -d
docker compose logs --tail 100 app
```

Перезапуск сохраняет профиль, события, задачи, версии и очередь. Не использовать `down -v`: это удалит volume с данными. Согласованная резервная копия: `docker compose exec -T app python -m app.operations backup /app/data/backups/review.sqlite3`. Используйте новое имя; файл не перезаписывается. Порядок проверки и восстановления описан в `docs/OPERATIONS.md`.

Без Docker:

```sh
python -m venv .venv
# Activate the venv for your shell.
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
python -m pytest -q
python scripts/export_api.py
```

Для актуального публичного контракта: `python scripts/export_api.py https://YOUR_APP_HOST`. Архив текущего кода: `python scripts/package_source.py`; результат и SHA256 сохраняются в `.local/release/` без секретов или базы. Полный комплект сдачи описан в `docs/SUBMISSION_CHECKLIST.md`.

## Основной сценарий проверки

1. В MAX открыть выданного бота `t647_hakaton_max_bot`, отправить `/start`, открыть mini-app после привязки организаторами. В браузере нажать «Попробовать с начала»: каждый новый вход создаёт пустой синтетический профиль. После onboarding в «Мои данные» доступны отдельно обозначенные независимые браузерные demo-пресеты.
2. Пройти язык → вуз → режим въезда → фактическая/планируемая дата → жильё → visa expiry при необходимости → согласие. Неизвестные данные можно пропустить.
3. В «Мои данные» уточнить возраст, учебное основание/статус, гражданство, цель и план >90 дней. Проверить несколько задач, документы, офис и источники. Для СПбГУПТД рекомендованное обращение для визы за 60 календарных дней; 50 календарных дней применяются только к регистрации по общежитию. Для ЛЭТИ «45 дней» остаётся текстом без вычисленной даты. «2 дня» СПбГУПТД и часы ЛЭТИ также не превращаются в неподтверждённую точную дату.
4. Изменить статус задачи, перезагрузить приложение: статус сохранится. Отметка выполнения — self-report, а не решение ведомства.
5. «Я сменил адрес»: выбрать дату и частный адрес, подтвердить. Появится соответствующий локальный порядок; прежний учёт получит requires_recheck с сохранённым выполнением. M09 не дублирует M03/M04.
6. В истории исправить или отменить событие: исходная запись остаётся, план восстанавливается по активным фактам. При отмене факта дактилоскопии восстанавливается предыдущий статус; повторный въезд не сбрасывает подтверждённую однократную процедуру.
7. В `/admin` войти ключом редактора своего вуза. Создать отдельное модельное правило, например уникальное действие «проверить комплект» для визовой ветки, якорь `visa_expiry`, тип `preparation_start`, сдвиг −65, единица calendar, рекомендация вуза, обе языковые версии, источник и модельное основание. Не менять публичную инструкцию настоящего вуза на произвольный срок.
8. Проверить validation → preview affected count и before/after → явное подтверждение → publish. Только затронутые планы получат изменение. Новая версия сохраняет статус того же действия. Повторный publish с тем же ключом не дублируется.
9. У студента MAX появится уведомление с пометкой демонстрационного изменения; состояние доставки видно редактору. Браузерные профили без MAX ID сообщения не получают.
10. В отдельной браузерной сессии повторить onboarding для ЛЭТИ. Тот же core выдаст другие инструкции, контакты и формулировки сроков.

## MAX и HTTPS

`PUBLIC_BASE_URL` — полный HTTPS URL приложения. `MAX_BOT_USERNAME` — username выданного бота. `BOT_TRANSPORT=polling` допустим для тестирования, только один экземпляр polling на бота. Для постоянного URL использовать `webhook` и подписку `/api/max/webhook` с `MAX_WEBHOOK_SECRET`: backend проверяет `X-Max-Bot-Api-Secret` и сохраняет update до ответа 200. Не запускать polling при активной webhook-подписке.

Ссылку mini-app передать через форму организаторов из FAQ. Сам токен не даёт права привязки. Подпись launch data проверяется сервером по официальному алгоритму HMAC с ключом `WebAppData`; initDataUnsafe используется только как необязательная подсказка навигации.

API MAX использует `platform-api2.max.ru` и сертификат Минцифры. Публичный CA получен по `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`; SHA256 DER: `d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`. Он добавляется только в отдельный TLS-контекст клиента MAX; проверка сертификата и hostname включена. ОС и другие приложения не изменяются. См. официальную документацию MAX `https://dev.max.ru/docs-api`.

Тестовый HTTPS можно поднять отдельно:

```sh
docker compose -f docker-compose.yml -f scripts/tunnel-compose.yml up -d
docker compose -f docker-compose.yml -f scripts/tunnel-compose.yml logs tunnel
```

Quick Tunnel даёт временный URL, который может поменяться при перезапуске. Перед сдачей заменить постоянным адресом. Внешние зависимости: MAX API/клиент, HTTPS provider; optional LLM API. Их нельзя воспроизвести локальным Docker.

## Данные, роли, языки

Хранятся MAX ID, вуз, минимальный профиль, даты, события и статусы. Нет загрузки документов, паспортных номеров, точного адреса, диагнозов и результатов исследований. Полное удаление из рабочей базы доступно студенту; очистка неактивных данных — `RETENTION_DAYS` (180 по умолчанию). Перед передачей реальных данных в пилоте требуется согласованный правовой режим обработки.

Inbox сохраняет только минимальную адресацию до обработки; затем остаётся обезличенный dedupe key. Адресация приветственного сообщения живёт до отправки/отмены либо не более суток. Удаление профиля очищает и эту очередь. Данные уже отправленных сообщений в самом MAX приложение не удаляет.

Сессии: Bearer token, в базе только SHA256, срок `SESSION_TTL_SECONDS`. Редакторы разделены по tenant. Maintainer имеет доступ к обоим локальным tenant; правовой seed изменяется разработчиком через источник и новую immutable version. В тестовой среде роли сотрудников модельные. Ключи не публиковать; для проверки жюри передать их служебным каналом.

RU/EN критические строки заданы явно в каталоге и UI; перед сдачей требуется человеческая языковая вычитка. Для текста есть локальный classifier/fallback и optional OpenAI-compatible `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Он предлагает только тип события и язык; даты/поля выбираются в форме. Профиль в prompt не передаётся. LLM не отвечает на юридические вопросы и не изменяет правила или roadmap. Другие языки не заявлены как проверенные.

## Контракт API и ограничения

`openapi.json` экспортируется из реально работающих роутов, OpenAPI 3.1. `DATA-API.yaml` описывает проверки и роли. `tests/fixtures/` содержит синтетические данные для API-теста; они не подставляются в пользовательский onboarding. Пересчёт, snapshot/history и outbox записываются транзакционно. Повторы пользовательских событий и публикаций защищены idempotency key. Перезапуск не теряет pending messages.

Транспорт MAX может принять сообщение, а соединение оборваться до ответа: без внешнего idempotency API нельзя гарантировать физическую exactly-once доставку. В БД одна логическая запись на revision; worker с lease/retry, редкий сетевой дубль описан как ограничение. SQLite и один worker подходят MVP, не кластерной нагрузке. Непроверенные договорные исключения, рабочий календарь, расписание офиса, РВПО/РВП/ВНЖ, несовершеннолетние и сложные статусы требуют review. См. `docs/IMPLEMENTATION_STATUS.md` и `docs/CODE_MAP.md`.

Коммиты в рамках разработки не создаются. Для фиксации конкурсной версии используйте архив с контрольной суммой, исключая `.env`, `.local`, `AGENTS.md`, данные и резервные копии.


## Браузерные демо-профили

После onboarding откройте «Мои данные»: исходный профиль и четыре независимых тестовых студента переключаются кнопками. Все планы вычисляет обычный rules engine. Статусы/события выбранных профилей сохраняются; неподтверждённые федеральные даты остаются неизвестными. На настоящем аккаунте MAX кнопок нет. Хранение и ограничения сессий — `docs/DEMO_PROFILES.md`.
