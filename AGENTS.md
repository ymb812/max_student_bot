# Передача изменений и ревью «Рядом»

- Перед задачей прочитай актуальную сводку `docs/CURRENT_REVIEW.md` и относящуюся к задаче часть `docs/CODE_MAP.md`. Сводка хранит статусы замечаний; требования остаются в спецификации и принятых решениях. Старые отчёты описывают свою версию, а не текущую готовность.
- Передавай на ревью конкретный commit и границы изменения. Не меняй проверяемое дерево во время ревью; для одновременной разработки используй отдельную рабочую копию. Не включай чужие правки в свой пакет. Порядок и короткий шаблон передачи находятся в `docs/CURRENT_REVIEW.md`.
- По завершении изменения или проверки обновляй затронутые строки сводки: ID, commit реализации, результат проверки и оставшиеся ограничения. «Реализовано» не означает «проверено»; локальная проверка не подтверждает выкладку. Новые замечания не означают разрешения на расширение задачи.
- Для изменений студенческих текстов проверяй согласованность затронутого сценария целиком: заголовок, срок, инструкция, ожидаемый результат, кнопка и справка, а при сохранении — результат и история. В `conditional`/`needs_review` неопределённость не должна превращаться в персональное требование или факт расчёта; общая инструкция допустима с явным условием применимости. Проверяй также стандартную ветвь, где прямое действие допустимо.
- При изменении текста проверь, не используется ли сравнение строк для выбора смысловых разделов. Новое поведение должно опираться на состояние/назначение раздела; допустимо сравнивать текст для удаления буквальных дублей, если это не меняет смысл. Проверка должна обнаруживать противоречащий текст, а не только наличие новой фразы. Не переписывай несвязанный код ради этого правила.
