# Реестр сроков хакатонного прототипа

Версия модели: `hackathon-2026-10-22-v1`. Реализация: `app/prototype_timing.py`. Машиночитаемый снимок исходных/демонстрационных правил: [PROTOTYPE_TIMING.json](PROTOTYPE_TIMING.json).

## Общие правила демонстрационного расчёта

- Календарный интервал: дата основания +/− число дней. День основания не считается первым днём интервала.
- Рабочие дни: понедельник–пятница, без государственных праздников и переносов. Например, 1 января может попасть в расчёт как рабочий день — это ограничение модели, не производственный календарь.
- Подтверждённые календарные рекомендации СПбГУПТД остаются прежними. Модель не превращает рекомендации в обязательные нормы.
- Медицинские интервалы применяются к заполненному поддерживаемому учебному профилю; таблица исключений по гражданству в демо не используется. Несовершеннолетие, другая цель въезда, особый статус и отсутствующие ответы не становятся автоматически стандартным сценарием.
- Неизвестная дата въезда/прибытия/окончания документа остаётся неизвестной; готовая дата не подставляется из тестового профиля или текущего дня.
- Новый медицинский факт задаёт следующий цикл через существующее событие `medical_completed`; прохождение дактилоскопии — через `fingerprinting_completed`. Это прежние события модели, без новых категорий и результатов. В демо карточки называют действие прямо и открывают эти формы.
- Для повторного обращения после изменения проживания сохраняются имеющиеся ограничения движка: в частности, новый срок первого визита ЛЭТИ не переносится автоматически на переезд.

## Включение, происхождение данных и возврат

Режим включается только явно: `prototype_timing=True` при `demo_mode=True`. В preview: `python scripts/preview_redesign.py --port 8015 --database .local/review-preview-20261022.sqlite3 --prototype-timing`. По умолчанию выключен. В обычном режиме действуют прежние `conditional`/`needs_review` и ограничения расчёта. Флаг demo_mode сам по себе допущения не включает.

Исходные опубликованные правила не переписываются. Допущения накладываются на копию правил при расчёте; каждому изменённому сроку добавляются версия модели и исходная спецификация. У вычисленной демонстрационной даты нет ссылки/даты проверки, выдающей модель за официальный источник. Исторические снимки сохраняют свою версию. Пользовательские и редакторские custom-правила модель не заменяет.

По уточнению пользователя 22.10 метка «Прототип / Prototype» убрана из общей шапки; место под неё не резервируется. Исследовательских абзацев в карточках нет; на справочном экране указано происхождение расчёта. Перед реальным выпуском каждое демо-допущение нужно заменить принятым продуктовым правилом; этот файл служит реестром таких замен.

Не расширено этим решением: новые основания пребывания, новые учебные статусы, различение выдачи и получения, модель отказа/возврата документов. Их отдельные решения остаются открытыми.
