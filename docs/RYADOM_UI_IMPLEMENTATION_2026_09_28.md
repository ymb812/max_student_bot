# Рядом: реализация экранной системы, 28.09.2026

## Основание и границы

Реализован новый student presentation layer по приложенному `RYADOM_FINAL_UI_UX_LOGIC_SPEC.md` и финальным коллажам. MASTER FINAL и research сохраняют приоритет по продукту и предметным правилам. Новый интерфейс не добавляет правовые нормы и не меняет eligibility. Макетные даты, количества, текущий этап и сюжеты diff не используются как константы.

В §9 приложенного документа есть расхождение с явным уточнением пользователя: первая пара M07/M08 упомянута в «После приезда». Принято уточнение пользователя: **M07/M08 по умолчанию в «Во время учёбы»**. Hero выбирается независимо от этапа: actionable/requires_recheck, незавершённое действие либо повторная проверка → now/soon/later → ближайшая практическая вычисленная дата → стабильный порядок. Дата окончания документа не используется вместо практического срока. Незавершённый M03 не блокирует M07.

Визуальная система: белый фон, синий акцент, светлые карточки, timeline, жёлтый блок уточнений, нижние вкладки «План / Событие / Мои данные», safe-area. SVG-иконки/CSS не содержат текстов или чисел из коллажа. Колокольчик без inbox отсутствует. Стили нового UI ограничены student-страницей, админка сохраняет свой интерфейс.

## Навигация и сохранность

Vanilla JS state machine и History API используют query `screen`, `stage`, `key`, `revision`, `eventId`. Это UI-состояние, а не новые server routes. Nested stack хранит origin/scroll. Back результата ведёт в актуальный план. Профиль и roadmap перечитываются после мутаций. Draft формы живёт в процессе UI; уход вызывает продолжить/не сохранять. Browser beforeunload и доступные MAX closing confirmation/BackButton подключены по [официальной документации MAX Bridge](https://dev.max.ru/docs/webapps/bridge).

MAX launch data по-прежнему проверяются сервером. `initDataUnsafe.start_param` используется только для навигации после auth. Существующие task deep links сохраняются, отсутствующая задача даёт нейтральный fallback. Реальный MAX receipt для новой версии ещё не получен.

## API

- `POST /api/me/events`, подтверждение candidate и отмена события возвращают `revision_id`.
- Событие без изменения задач тоже имеет сохранённую ревизию с `changes=[]`. Такое событие не создаёт уведомления roadmap_changed.
- `GET /api/me/history/{revision_id}` возвращает только собственную ревизию. Чужая/неизвестная — 404.
- `GET /api/me/history?offset=...` возвращает до 100 ревизий и `next_offset`; порядок стабилен по created_at/id.
- Повтор POST с прежним ключом возвращает исходное событие/ревизию. При потерянном сетевом ответе UI сначала ищет записанное событие по idempotency key, затем читает его diff.
- Правила/даты/эпизоды/источники/контакты движка не перенесены в frontend. `missing_fields`, `episode_id`, `cycle_id`, `semantic_action_key`, temporal owner/kind уже были доступны в существующем response.

## Проверка

Изолированный локальный сервер: `python scripts/preview_redesign.py`; БД `.local/ryadom-ui-acceptance.sqlite3`, без транспорта MAX. Проверки:

```text
python -m pytest -q
node --test tests/roadmap-view.test.cjs
node --check app/static/student.js
node --check app/static/student-ui.js
node --check app/static/roadmap-view.js
node scripts/check_student_ui.cjs
```

Browser smoke использует установленный Chrome и Playwright (`PLAYWRIGHT_MODULE` при нестандартном расположении пакета). Скриншоты реального локального UI — `.local/ryadom-ui/`, все профили синтетические. Скрипт проверяет onboarding, согласие, этапы/Back, conditional editor/dirty guard, несколько вопросов и один PATCH для M01 СПбГУПТД, профиль, статус/reload, review, событие/исправление/отмену/result/reload/history, RU/EN и отсутствие горизонтального переполнения на 320/360/390/768 px. Отдельные проверки покрывают выбор настоящей M07 при текущем arrival, её наличие в study, подтверждение переезда в другое место того же типа, потерянный ответ POST, возврат браузером из результата и persisted empty diff.

Backend: 36 тестов; presentation: 4 теста. Тесты подтверждают фильтрацию неопределённых/старых задач, семантическую дедупликацию, старое completed+recheck вне числителя, доступность будущего этапа, приоритет bucket перед датой, запрет чужого revision и replay receipt.

## Ограничения приёмки

- Экранная система выложена на тестовый HTTPS 28.09.2026; публичные health/assets/browser/API проверки описаны в `DEPLOYMENT.md`. Приёмка нового UI на настоящем MAX/телефоне ещё не выполнена.
- Нужны устройство/клавиатура/safe-area/VoiceOver/TalkBack и человеческая RU/EN вычитка. Браузерный viewport не заменяет эти проверки.
- Необязательный свободный комментарий события не добавлен в строгую backend-модель: сохраняются только существующие типизированные поля. Свободный текст работает как предложение типа через прежний candidate API.
- Для первого ввода известной даты въезда и известного жилья создаётся типизированный entry event. Если жильё неизвестно, дата остаётся исходным фактом профиля: текущая строгая event schema требует известный residence_type. Планируемая дата никогда не становится фактическим событием.
- Презентация/PDF/PPTX не пересобирались; в `PRESENTATION_CONTENT.md` указано, какие реальные снимки подставить. Коммитов нет.
