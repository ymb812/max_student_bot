# Рядом — внедрение activation-v3, 18.10.2026

## Результат и границы

Обновлён студенческий мобильный интерфейс по внешнему прототипу версии activation-v3. Пользователь сохранил исходные макеты и handoff вне проекта; локальная копия прототипа исключена из Git и Docker-контекста и не используется как источник требований. Для дальнейшей разработки используются [CODE_MAP](CODE_MAP.md), [UI/UX spec с дополнением 18.10.2026](RYADOM_FINAL_UI_UX_LOGIC_SPEC.md) и этот самодостаточный отчёт: экранное соответствие, принятые решения, ограничения и критерии приёмки приведены ниже. Продукт, правила и формальные требования по-прежнему определяются MASTER FINAL, research и официальными документами кейса; макет не требуется перечитывать.

Внедрение — vanilla JS/CSS в существующем presentation layer. Каталог M01–M10, engine/service, применимость, четыре вида дат, источники, эпизоды, циклы, версии, приоритеты, MAX auth, reminders, candidate API и админка сохранены. Приложение и проверки не зависят от файлов внешнего макета; все необходимые ресурсы находятся в `app/static/`, включая `ryadom-logo.svg`. Во время внедрения исходный прототип не редактировался; после сохранения пользователем внешней копии локальная папка исключена из Git и Docker-контекста. Публикация, deployment, обращение к тестовому/продуктовому серверу и Git commit не выполнялись.

## Что изменено

- Сине-голубая система: фон `#f7f9ff`, основной синий `#2451d9`, насыщенный Hero, белые/голубые карточки, компактная шапка и нижняя навигация. Использован SVG-логотип прототипа. Фиолетовых student-акцентов нет.
- Четыре вопроса: ситуация → вуз → режим въезда → жильё. Карточка выбирает ответ; следующий экран открывается только по кнопке. Возврат, browser/MAX Back и session draft сохраняют ответы. Имя, отдельный выбор языка, splash и Aha в основном пути отсутствуют.
- Полное существующее согласие с условиями обработки, минимизацией, удалением и настроенным сроком хранения; впервые не отмечено. Последняя кнопка заблокирована до явного согласия. Запись — прежний PATCH профиля; ошибка не переводит локальный профиль в consent=true и допускает повтор.
- Настоящий RU/EN в шапке и редакторах. Перевод меняет тексты и сохранённый язык, сохраняя радиоответы, согласие, даты, select, checkbox и введённый текст предложения события. Локальные черновики ограничены текущей авторизованной browser session, не заменяют серверные факты.
- Общая линия маршрута; завершённый этап — синий круг с галочкой и текстом завершения; текущий — обведённый маркер, голубая карточка и «Вы сейчас здесь»; незавершённый вне текущего контекста — пустой маркер. Все этапы доступны.
- Полные реальные списки этапа, раскрываемые завершённые, обратимая ручная отметка конкретной задачи. После завершения доступно следующее реальное действие; Hero пересчитывается из актуального snapshot. Нет общего переключателя завершения этапа.
- Без кандидата Hero показывает честное отсутствие текущих действий и ведёт к уточнению. Уточнение даты фактического въезда использует полную существующую форму события (неизвестный тип жилья требует явного выбора); планируемой даты — редактор профиля. Ни даты, ни событие не создаются из ответа «Уже в России».
- Сохранены все 12 типов событий, LLM/candidate предложение, история и её фильтры, исправление/отмена, no-diff, источники, удаление и управление reminders. Задача с completion_basis=reported_fact или superseded ведёт в историю, без ручной смены факта.
- Источник вложенного экрана и стек сохраняются до начальной загрузки: reload больше не теряет возврат из задачи в этап. Типизированные черновики событий/редакторов восстанавливаются после reload; idempotency key сохраняется при переводе/reload. После успешного сохранения/сброса черновик очищается, при удалении профиля очищаются и его session drafts.

## Согласованное дополнение контракта

Пользователь выбрал добавление необязательного `Profile.arrival_status` вместо дополнительного обязательного запроса даты перед Планом.

- Enum `planned | arrived | unknown`, default `unknown`; старый клиент может не передавать поле.
- Хранится прежним JSON-профилем в SQLite и возвращается профильным API. SQL-миграция не требуется.
- Это **только контекст интерфейса**. Engine не использует его для eligibility, вычисления срока, подтверждения въезда, завершения задачи или открытия эпизода. Тест сравнивает задачи и decisions при смене только этого поля.
- Без `entry_at` ответ arrived выделяет контекст «После приезда», но не выдаёт вымышленного прогресса. При наличии фактической даты действуют прежние факты и алгоритм текущего этапа. Начальное before не становится завершённым от приезда.
- Ситуацию можно исправить в «Мои данные». Дата, планируемая дата и основание въезда остаются самостоятельными сведениями.
- `openapi.json` пересобран: изменение схемы — только это необязательное поле. DATA-API и существующие HTTP-методы сохранены.

## Приёмка

Среда: локальный Chrome headless через Playwright, изолированный FastAPI на `127.0.0.1:8010`, БД `.local/ryadom-ui-acceptance.sqlite3`, synthetic profiles, bot transport disabled. Внешний MAX JS в browser automation блокируется, поэтому это не MAX-приёмка.

| Критерий handoff | Результат |
|---|---|
| 1. Четыре вопроса → План; ответы можно исправить | PASS: явное продолжение, возврат с ответом, RU/EN/reload, housing unknown, consent false→true, неудачный PATCH и успешный повтор; ситуация/профиль редактируются |
| 2. Поздний вход; прошлый этап, отметка и снятие | PASS: реальная M02 из полного roadmap; завершение/отмена меняют прогресс; никакого опроса о прошлых этапах |
| 3. Полные списки, следующий Hero, пустой этап | PASS: >5 серверных задач, полная выдача этапа; следующий task_key после завершения; undo возвращает прежний Hero; нулевой denominator без progress/галочки |
| 4. Unknown/recheck отличаются от выполнения | PASS: отсутствие даты/entry event, нет вычисленных сроков при неполных данных; recheck и superseded без ручных кнопок; presentation-тест completed+recheck вне числителя |
| 5. API событий, исправление/отмена, эпизод/no-diff/retry | PASS: въезд, переезд, исправление/отмена; same-type move; потерянный ответ уже записанного POST восстанавливается без дубля; пустой diff после повторного факта сохраняется и после reload |
| 6. RU/EN, origin/Back/reload | PASS: quiz, task→origin stage после reload; typed event + текст предложения и field sheet сохраняют значения при переводе/reload; event key неизменен; dirty guard сохраняет форму |
| 7. Мобильная компоновка | PASS в браузере: 320/360/390 px, RU/EN, основные экраны, все видимые кнопки ≥44×44; длинный список истории/событий, полный текст задач; редуцированный viewport 320×480 позволяет доскроллить до Save |

Новый script проверяет recheck, read-only, загрузку истории, GET error/retry, удаление профиля с отзывом сессии. Ошибок JavaScript в обеих сессиях нет.

## Оставшиеся ограничения

- **Внутри MAX на физическом телефоне эта версия не проверялась.** Нет нового доказательства по реальному MAX Back, закрытию/reopen WebView, входу из push, экранной клавиатуре, ненулевой safe-area и VoiceOver/TalkBack. Изменённый UI не деплоился; автоматизация использует обычный локальный Chrome.
- Сжатие viewport до 320×480 проверяет доступность прокрутки/Save, но не заменяет настоящую клавиатуру и WebView.
- Для существующих профилей без arrival_status сохраняется прежний контекст по фактическим данным; приложение не угадывает ситуацию. Смена ситуации не отменяет ранее записанное событие — исправление/отмена доступны в истории.
- Смена уже выбранного вуза по-прежнему ограничена backend 409 и review перевода; редизайн не обходит это продуктовое ограничение.
- Подтверждение фактического въезда требует дату и весь поддерживаемый payload. Пока дата/жильё неизвестны, пользователь остаётся с честными conditional/needs_review; никакого фиктивного факта ради макета.
- Локальные drafts восстанавливаются в той же browser session с действующей авторизацией. Перенос черновиков между устройствами не добавлен; сохранённый профиль, задачи, consent и история остаются серверными. Поле ситуации сохраняется на сервере.
- Окончательная человеческая RU/EN вычитка и устройство остаются отдельным этапом приёмки. Правовые факты/контакты не переисследовались, каталог не менялся.

## Вынос исходного прототипа из проекта

18.10.2026 пользователь подтвердил сохранение исходного прототипа вне проекта. Корневая директория макета на момент проверки не отслеживалась Git. Добавлены исключения в `.gitignore` и `.dockerignore`; папка не включается в изменения и Docker build context. Физическая очистка локальной копии пока не выполнена и не является условием сборки или проверок. Актуальные требования перенесены в документы проекта, ссылок с требованием читать внешний handoff нет. Название версии в этом отчёте и `output/activation-v3/` обозначает историю реализации и генерируемые скриншоты, а не зависимость от исходной папки макета. Приложение, тесты и скриншоты сохранены; исходный внешний архив не изменялся.
