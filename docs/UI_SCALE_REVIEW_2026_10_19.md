# Проверка масштаба и интерфейса, 19.10.2026

## Результат и область

Полная (`full`) проверка текущего student UI по двум пользовательским снимкам и работающему приложению. Стек — vanilla JS/CSS, существующая система activation-v3; новых зависимостей и UI-библиотек нет. Проверены приветствие, четыре вопроса, План, все этапы, задача, уточнения, review, все 12 форм событий, результат/diff, история, профиль и редакторы.

На снимках менялся размер контейнера по высоте, а не масштаб браузера. При viewport 1920×1320 до исправления у приветствия были ширина 430 px, высота 820 px, верхний отступ 24 px и радиус 28 px. Первый вопрос имел ту же ширину, но высоту 1320 px, нулевой отступ и радиус. У body приветствия высота составляла только 820 px: фон под карточкой отличался от фона вокруг нее.

Теперь один `.ryadom-shell` используется во всем student UI. На широких экранах он имеет ширину до 430 px, общие границу, скругление и отступ 24 px. Минимальная высота — меньшая из 820 px и доступной высоты окна за вычетом внешних отступов. Длинное содержимое увеличивает документ и прокручивается обычным window scroll; внутренний scroll-container для страниц не добавлен. На мобильном экране оболочка занимает доступную высоту без внешней рамки. Приветствие и первый вопрос в высоком desktop-окне теперь имеют одинаковый bounding box.

Меняются только presentation styles и cache version в HTML. Четыре вопроса, согласие, auth, черновики, history/Back, серверные факты и расчет маршрута сохранены. Настоящие профили для приемки не изменялись.

## Рассмотрено и отклонено

| Location | Candidate | Rejected because |
|---|---|---|
| Desktop shell | Растянуть контент на всю ширину монитора | Утвержденная композиция mini-app ограничена 430 px; проблема вызвана разной высотой оболочки |
| Welcome/question headings | Сделать все заголовки одного размера | Приветствие и вопрос имеют разную иерархию; ширина страницы не менялась, тексты читаются и не обрезаются |
| Frame height | Жестко задать 820 px всем экранам, включая мобильные | Маленькое окно, согласие и длинные формы должны прокручиваться без обрезки; общий minimum допускает рост по содержимому |

## Проверки и ограничения

- `node scripts/check_student_layout.cjs`: **448** RU/EN проверок на 320×640, 390×844, 430×932, 768×1024, 1280×720, 1920×1320 и 2560×1350. Включены все 12 event forms, shared welcome/questions bounding box, полный фон, отсутствие горизонтального overflow, кнопки >=44×44 px, границы dialogs, desktop tabs внутри frame, window scroll и контраст Hero CTA.
- Скриншоты и числовой отчет — `output/layout-review/`. Визуально просмотрены desktop приветствие/первый вопрос, мобильный План, длинная EN-форма на 320 px и desktop editor. Геометрические проверки остальных состояний автоматические; полный pixel-by-pixel просмотр всех снимков не заявлен.
- `node scripts/check_welcome_ui.cjs`, `node scripts/check_activation_ui.cjs`, `node scripts/check_student_ui.cjs`: все прежние browser-сценарии проходят, включая ответы/согласие/RU/EN/reload/Back, события, статусы, исправление/отмену, diff, dirty guard и повтор запроса.
- `python -m pytest -q`: **38 passed**; `node --test tests/roadmap-view.test.cjs`: **6 passed**; JS syntax и `git diff --check` проходят.

**Verdict: Approve в проверенной браузерной области.** Не проверены: новый CSS внутри настоящего MAX на физическом телефоне, экранная клавиатура устройства, native browser zoom пользователя и Safari/Firefox. Chromium/Chrome и размеры CSS viewport проверены. Результаты прежней MAX-приемки не подменяют эти отдельные проверки.
