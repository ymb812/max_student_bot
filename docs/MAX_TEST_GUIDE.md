## HTTPS на сервере

Сертификат доверенного CA и его автоматическое продление можно настроить на сервере. Самоподписанный сертификат не подходит: официальная документация MAX не поддерживает его для webhook; embedded клиент также должен доверять TLS.

Проверено 27.09.2026: общий `wb_caddy` обслуживает 80/443 и отдельный host max.market-kit.ru через внутреннюю сеть max_edge. Host port app остаётся 127.0.0.1:8097. Пользователь явно разрешил минимальное изменение общего Caddy; исходные маршруты сохранены, основной сайт HTTPS 200 и его сертификат не изменился.

Для постоянного URL на этом сервере нужна отдельная маршрутизация в общем proxy и подтверждённое имя/адрес. Домен не является технически обязательным: Let's Encrypt с января 2026 выпускает сертификаты IPv4/IPv6 на 160 часов с обязательной частой автоматизацией продления. IP validation требует HTTP-01 или TLS-ALPN-01 на стандартных портах. Совместимость конкретного IP URL с привязкой MAX заранее не заявляется проверенной. Поэтому выпуск IP-сертификата не устраняет необходимость согласовать маршрут через занятые 80/443. Для доменного варианта нужен DNS, указывающий на сервер; остальные команды TLS выполняет разработчик.

Источники: https://dev.max.ru/docs/webapps/introduction ; https://dev.max.ru/docs-api/methods/POST/subscriptions ; https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/ ; https://letsencrypt.org/2025/01/16/6-day-and-ip-certs/ . Проверено 27.09.2026.

## Сценарий настоящей проверки (запуск и сохранение статуса уже пройдены)

1. На телефоне открыть бот, нажать старт или отправить `/start`, затем открыть mini-app кнопкой внутри MAX. Браузерный «Попробовать с начала» не заменяет этот тест.
2. Пройти onboarding на синтетических данных: язык, вуз, режим въезда, даты, жильё, согласие. В профиле уточнить взрослую учебную ветку. Проверить источники и разные типы времени; unknown должен оставаться review без выдуманной юридической даты.
3. Изменить статус одной задачи, закрыть mini-app и открыть снова. План и статус должны сохраниться. При настоящем входе нет баннера браузерного demo.
4. Подтвердить смену адреса на частный, проверить пересчёт и recheck прежнего учёта. Исправить/отменить событие и проверить восстановление.
5. Повторить открытие в web MAX своим аккаунтом. Не передавать разработчику пароль или initData: backend проверяет подпись автоматически.
6. Тест публикации для согласованного аккаунта уже выполнен и подтверждён пользователем; временное правило архивировано. Для повторного показа жюри создавать отдельное явно модельное правило с validation → affected preview → подтверждением → publish; выбирать только согласованные тестовые профили. Произвольным демосроком нельзя менять официальное правило вуза.
7. Повторить учебный сценарий для второго вуза на другом тестовом аккаунте либо в отдельно согласованном тестовом профиле. Не удалять реальный профиль ради теста без намерения пользователя.

Для сообщения разработчику достаточно: «URL привязали; открыл /start и mini-app; время МСК; устройство и версия клиента; результат/текст ошибки». Номера паспорта, сканы, медицинские данные и токены не нужны. Разработчик проверяет подпись, запись события, пересчёт и доставку по обезличенным диагностическим признакам.
